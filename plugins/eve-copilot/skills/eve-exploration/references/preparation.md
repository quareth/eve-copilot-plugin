# Preparation profile

Use this profile before undocking, when entering a new operating area, or when
the pilot asks for a comprehensive route or expedition plan.

## Build the expedition profile

Query the MCP first. Derive current system, ship, active fit, relevant skills,
fleet membership, available support hulls, and authorized bookmarks from tools
rather than a questionnaire. Infer stated preferences from the conversation.

Ask only for unresolved, non-queryable decisions that materially change the
plan. Usually these are target site families, allowed security spaces, loss
tolerance, session duration, mandatory return, avoidance systems, and private
wormhole connections not represented in accessible bookmarks. Ask once, in a
compact group. If the pilot says "choose for me," state sensible assumptions
and proceed.

## Plan in six passes

1. **Eligibility:** classify which ordinary, guarded, timed, and hazardous
   sites the current fit can safely attempt. Reject targets requiring a cloak,
   nullifier, probe/analyzer strength, tank, combat, cargo, or wormhole mass
   profile the fit does not have.
2. **Area selection:** choose two or three candidate pockets, constellations,
   sovereignty-upgrade neighborhoods, or wormhole entry strategies. Use SDE
   structure and current public data, not a fixed "best region."
3. **Known-space activity:** obtain complete relevant jump and kill rows for
   the candidate systems. Compare recent competition and PvP indicators. State
   snapshot freshness and unknown coverage.
4. **Route construction:** use gate-route calculations for candidate ingress,
   bounded loops, and extraction legs. Penalize repeated choke points,
   backtracking, ship-specific exposure, and a fragile return path. Treat a
   wormhole connection as an edge only when the pilot or an authorized mapper
   observed it.
5. **Route scoring:** rank whole route policies, not just isolated systems.
   Balance expected eligible systems per minute, recent danger, travel cost,
   uncertainty, return credibility, and cargo exposure.
6. **Operational plan:** define the first hop, checks on arrival, replanning
   triggers, cargo/time extraction thresholds, and at least one alternative.

Do not make false precision the centerpiece. If numeric scores help compare
candidates, show their ingredients and make clear that they are relative
estimates, not probabilities of finding a site.

## Preparation output

Use this compact structure:

1. **Expedition profile:** facts from MCP, user choices, and explicit
   assumptions.
2. **Primary policy:** ingress, search loop or chain strategy, and extraction.
3. **Why it ranks first:** opportunity, risk, travel, and uncertainty evidence.
4. **Alternatives:** at least one fallback with its tradeoff.
5. **Arrival procedure:** what to check in every new system.
6. **Abort/extract triggers:** concrete conditions that end or redirect the
   expedition.
7. **Unknowns:** only facts that could not be retrieved or observed.

For a fleet, assign roles and branches. For a solo pilot, reserve enough time
and route credibility to extract accumulated loot.
